## H0. Гигиена форка — `[ ]` (сделать первым)

Репозиторий остаётся **публичным** (решение от 2026-11-06). Поэтому в git не кладём IP и домен сервера,
реальные имена и телефоны — агенты это соблюдают.

1. **`main` от релиза.** Локально уже сделано: `main` = `v4.19.1`, `feature/initial_setup` от него. Осталось
   обновить GitHub: `git push -f origin main` (там `main` всё ещё указывает на develop-коммит). Готово `[ ]`
2. **Отключить upstream-автоматику в GitHub:** Actions → каждый upstream-воркфлоу → «Disable workflow» (или
   Settings → Actions → разрешить только воркфлоу, которые мы добавим). Dependabot: Settings → Code security →
   выключить version updates. Для публичного репозитория минуты Actions бесплатны, но upstream-воркфлоу будут
   падать без секретов, а `stale`/`lock`/`auto-assign` — трогать issues и PR. Готово `[ ]`
3. По желанию: `gh auth login`, чтобы агенты могли смотреть статус CI. Готово `[ ]`

## H1. Хостинг — `[ ]`

Бесплатные «pages» (GitHub/Cloudflare Pages, Vercel и т. п.) не подойдут: там только статика или короткие
функции. Chatwoot и Evolution API — постоянно работающие серверы с базой и долгими WebSocket-соединениями
к WhatsApp. Нужен VPS: **2 ГБ RAM (+ swap, его настроит агент), 1–2 vCPU, 30–40 ГБ SSD**, Ubuntu 24.04 LTS.
Весь стек в покое должен занимать ~1.1–1.3 ГБ, агент уточнит цифры на этапе 0. 4 ГБ дают запас, но не обязательны.

Варианты:
- **0. Существующий сервер с твоими Kamal-проектами.** Kamal-proxy общий, так что технически это проще всего, если
  там свободно ≥1.5 ГБ RAM. **Но** проект окажется на одном IP и в одном аккаунте хостинга с твоими личными
  проектами, и их легко связать (IP, DNS, сертификаты в публичных CT-логах). Плохой вариант, если анонимность
  важна.
- **A. Дешёвый VPS с оплатой криптой или без KYC** (~$5–10 в месяц). Лучший вариант для анонимности. Выбрать
  провайдера с хорошей репутацией и нужной юрисдикцией.
- **B. Обычный VPS** (Hetzner, DigitalOcean и т. п., ~€5–8 в месяц). Надёжно и просто, но аккаунт привязан
  к личности и карте.
- **C. Oracle Cloud Always Free** (ARM, до 4 ядер и 24 ГБ бесплатно). Бесплатно, но нужна карта и реальные
  данные, бывают проблемы с регистрацией, Oracle может забрать «простаивающие» инстансы. Образы должны
  поддерживать arm64.

Рекомендация: **A**, если анонимность приоритетна, иначе **B** (или **0**, если анонимность всё-таки не критична).

Ответ: провайдер ____, IP ____, архитектура (x86_64/arm64) ____

## H2. Домен — `[ ]`

Нужен для HTTPS. Варианты: домен у регистратора с приватностью WHOIS (оплата криптой у некоторых) или

Менеджер Evolution API наружу не публикуется, к нему ходят через SSH-туннель.

## H6. Подключение первого номера — `[ ]` (во время этапа 3)

Агент покажет QR. На Android, в WhatsApp нужного номера: «Связанные устройства» → «Привязка устройства» →
отсканировать. Важно:
- телефон с этим номером должен оставаться включённым и с интернетом хотя бы иногда (WhatsApp отключает
  связанные устройства, если основной телефон ~14 дней не был онлайн);
- для первого подключения лучше взять номер с наименьшим потоком клиентов;
- после подключения можно продолжать пользоваться WhatsApp на телефоне, сообщения синхронизируются.

## H13. Токен GHCR для деплоя — `[ ]` (до этапа 2)

Образ собирается в GitHub Actions и кладётся в GitHub Container Registry (публичный пакет, бесплатно;
Docker Hub не используем). Kamal всё равно логинится в registry, поэтому серверу нужен токен на чтение пакетов: GitHub → Settings → Developer settings → Personal access tokens → fine-grained
или classic с правом `read:packages`. Сам токен сюда не пиши, сохрани в менеджере паролей и передай агенту
в сессии. Готово `[ ]`
